### Windows 11에서 터미널 없이 릴리스 서명하기

1. 위 서명용 ZIP 전체를 압축 해제합니다. 이 패키지에는 이미 빌드한 웹 화면과 안드로이드 네이티브 의존성이 들어 있어 npm 설치가 필요하지 않습니다.
2. Android Studio에서 **File → Open**을 누르고 압축을 푼 `PDF_VIEWER_M/android` 폴더를 엽니다. 부모 폴더를 열지 마세요.
3. Gradle 동기화를 기다립니다. 의존성 다운로드에 인터넷이 필요합니다. SDK 35와 Gradle JDK 21을 사용합니다.
4. **Build → Generate Signed App Bundle or APK → APK**를 선택합니다.
5. **Create new**로 저장소 밖의 개인 폴더에 전용 서명 키를 만들고 안전하게 백업합니다. 키와 비밀번호를 GitHub나 채팅에 올리지 마세요.
6. **release**를 선택해 완료합니다. 생성된 APK는 Android Studio의 완료 안내에서 찾을 수 있습니다.

서명용 ZIP은 미서명 릴리스 빌드로 검증했습니다. 개인 키로 서명한 최종 APK와 실제 기기 설치 검증은 아직 완료하지 않았습니다. 상단 설치용 APK는 취약점을 수정한 **디버그 서명 버전**이며, 외부 설치 안내가 사라지는 것은 아닙니다.

### 1.0.1 보안 수정

PDF 엔진을 `pdfjs-dist 6.2.108`로 업데이트해 GHSA-hq66-cqwq-w95j 취약점을 수정했습니다. npm 보안 감사, 기존 기능 테스트, Android 빌드와 lint로 확인했습니다. 검사 결과는 실행 시점의 알려진 취약점에 대한 결과이며 Google의 안전 인증이 아닙니다.

모바일용 로컬 PDF 뷰어 **여백**입니다. 안드로이드에서는 APK를 설치해 서버 없이 실행할 수 있으며, 웹 버전도 제공합니다. PDF는 서버로 업로드하지 않고 앱 또는 브라우저의 IndexedDB에 저장합니다. 읽기 설정은 localStorage에 저장하며 PDF 처리 라이브러리와 워커도 앱에서 제공합니다. 사용 중 외부 API, 계정, 클라우드 저장소가 필요하지 않습니다.

## 안드로이드 APK 설치 (터미널 불필요)

`releases/yeobaek-1.0.1.apk`를 휴대폰에 다운로드하고 파일 앱에서 열어 설치하세요. 브라우저 또는 파일 앱에 ‘이 출처의 앱 설치 허용’이 필요할 수 있습니다. 설치 후 **여백** 아이콘을 누르고 **PDF 추가**로 휴대폰 파일을 선택하면 됩니다. 실행에는 PC, 개발 서버, 인터넷 연결이 필요하지 않습니다.

Android 8.0 이상과 Android System WebView 109 이상이 필요합니다. WebView가 오래된 경우 앱 안내에 따라 Play 스토어에서 Android System WebView/Chrome을 업데이트하세요. PDF 엔진은 호환성용 빌드를 사용합니다. 상태바·내비게이션바 영역을 피하고 안드로이드 뒤로가기 버튼은 설정 창 닫기 → 책장으로 돌아가기 → 앱 종료 순서로 동작합니다.

이 APK는 직접 설치하는 개인 사용용 디버그 서명 빌드입니다. Play 스토어에 게시한 앱은 아닙니다. PDF·설정·북마크는 앱 내부 WebView 저장소에 남습니다. 웹 브라우저의 기존 책장은 자동으로 가져오지 않으므로 파일을 다시 추가하세요. 앱을 삭제하거나 앱 데이터를 지우면 책장도 삭제됩니다. 원본 PDF는 별도로 보관하세요.

APK 빌드 및 서명 검증과 웹 기능 자동 테스트를 수행했습니다. 이 환경에는 안드로이드 기기/에뮬레이터가 없어 실제 기기 설치·파일 선택·실행은 아직 검증하지 못했습니다.

### 개발자가 APK를 다시 빌드할 때

JDK 21, Android SDK (API 35 / Build Tools 34 이상), Node.js, Python 3이 필요합니다. 개발 기기에서는 `JAVA_HOME`과 `ANDROID_HOME`을 설정하세요. 준비된 클라우드 환경에서는 설치된 `/workspace/android-tools/jdk`와 `/workspace/android-sdk`를 자동으로 사용합니다.

```sh
npm ci
npm run android:apk
```

웹 빌드 → Capacitor 동기화 → 안드로이드 APK 빌드와 lint → `releases` 복사 및 SHA-256 생성 순서로 실행합니다. 서명 키는 저장소에 포함하지 않습니다. 개인용 APK를 업데이트할 때는 동일한 디버그 키를 유지해야 합니다. 배포용 릴리스는 별도 릴리스 서명 설정이 필요합니다.

## 웹 버전 개발 실행

Node.js 22.13 이상 또는 24 이상이 필요합니다. 이 환경에서는 Node.js 24로 검증했습니다.

```sh
npm ci
npm run dev
```

터미널에 표시되는 주소로 접속합니다. 휴대폰과 실행하는 컴퓨터가 같은 Wi-Fi에 있으면 컴퓨터의 LAN IP와 5173 포트로 접속할 수 있습니다. 방화벽에서 해당 포트의 로컬 네트워크 접근이 허용되어야 합니다. 휴대폰에서 localhost는 컴퓨터가 아니라 휴대폰 자체를 가리킵니다. 클라우드 환경에서 실행할 때에는 플랫폼이 제공하는 접속 경로가 있어야 합니다.

배포용 빌드를 로컬에서 실행하려면:

```sh
npm run build
npm run preview -- --port 4173
```

주소의 프로토콜·호스트·포트와 브라우저가 달라지면 별개의 책장입니다. 컴퓨터에서 추가한 PDF가 휴대폰으로 자동 동기화되지는 않습니다. 휴대폰 브라우저에서 파일을 직접 선택해 주세요. 브라우저 데이터를 지우거나 시크릿 모드를 종료하면 저장 내용이 없어질 수 있으므로 원본 PDF는 별도로 보관하세요. 서버가 켜져 있어야 앱에 새로 접속할 수 있습니다. 웹 버전의 서비스 워커 기반 오프라인 재접속과 OCR은 이번 버전에 포함하지 않았습니다. 안드로이드 APK는 서버 없이 실행할 수 있습니다.

## 사용

- **PDF 추가**: 여러 파일을 한 번에 선택하거나 책장에 끌어다 놓습니다. PDF 첫 페이지가 표지로 표시됩니다.
- **책 관리**: 책 아래의 `…`에서 제목과 시리즈를 바꾸거나 삭제합니다. 원본 PDF 파일명과 내용은 변경하지 않습니다.
- **시리즈**: 새 시리즈 만들기에서 이름과 책을 선택합니다. 왼쪽 메뉴 또는 모바일 상단에서 해당 시리즈만 볼 수 있습니다. 책 관리에서 시리즈 이름을 비우면 묶음이 해제됩니다.
- **정렬**: 업로드 순서(먼저 추가한 순서) 또는 제목 순서. 즐겨찾기는 항상 위에 고정되며 즐겨찾기 안에서도 선택한 정렬이 적용됩니다. 연속 보기는 필터에 상관없이 전체 책장의 현재 정렬 순서를 따릅니다.
- **읽기**: 표지나 제목을 누르면 읽던 페이지를 엽니다. 좌우 넘김은 스와이프, 하단 화살표, 이전/다음 버튼, 키보드 좌우 방향키로 이동합니다. 스크롤 모드에서는 위아래로 읽습니다. 하단 가로 슬라이더로 원하는 PDF 페이지에 바로 이동합니다.
- **도구**: 본문 터치로 상·하단 도구를 숨기거나 표시합니다. 오른쪽 위의 검색, 북마크, 다른 PDF, 설정을 사용할 수 있습니다. 도구가 숨겨져도 상단 `…`로 다시 표시할 수 있습니다.
- **설정**: 명조/고딕/고정폭 글꼴, 글자 크기, 행간, 여백, 기본 도구 표시, 5가지 테마(화이트/다크/샌드/세이지/미스트), 들여쓰기, 연속 보기를 제공합니다. 글꼴은 기기에 설치된 시스템 글꼴을 사용합니다.
- **연속 보기**: 마지막 페이지에서 다음을 누르면 정렬상 다음 PDF의 읽던 위치로 이동합니다. 마지막 책에서는 종료 안내가 표시됩니다.

## PDF 텍스트와 원본

웹소설 텍스트 보기는 PDF 텍스트를 추출해 PDF 페이지 단위로 표시합니다. 글꼴·크기·행간·들여쓰기는 텍스트 보기에만 적용됩니다. 원문 PDF가 다단 구성이나 복잡한 레이아웃이면 추출 순서와 줄바꿈이 다를 수 있습니다. 들여쓰기는 추출된 각 문단의 첫 줄에 적용됩니다. 변경한 글자 크기에 따라 한 PDF 페이지 안에서 세로 스크롤이 필요할 수 있으며, 화면 크기별 재페이지화는 하지 않습니다.

텍스트가 없는 스캔 페이지는 자동으로 원본을 표시하며 OCR과 본문 검색은 지원하지 않습니다. 언제든 설정에서 PDF 원본 보기로 전환할 수 있습니다. 원본 캔버스는 화면 주변 페이지만 렌더링해 메모리 사용을 줄입니다. 암호로 잠긴 PDF는 잠금을 해제한 뒤 추가해야 합니다.

## 검증

```sh
npm test
npm run build
CHROMIUM_PATH=/path/to/chromium npx playwright test
```

Playwright 설정은 기본적으로 `/usr/bin/chromium`을 사용합니다. 해당 경로가 없는 기기는 설치된 Chromium 경로를 `CHROMIUM_PATH`로 지정하세요. 브라우저 테스트는 합성 PDF로 모바일 업로드·즐겨찾기·이름 변경·시리즈·검색·북마크·테마·글자 크기·위치 복원·연속 보기·원본 렌더링·삭제와 데스크톱 레이아웃을 검증합니다.
